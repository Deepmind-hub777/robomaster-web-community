# EP Core 技术探针包

这是一份教室现场探针准备包，目标是先判断本地桥接与浏览器控制是否值得继续投入。所有真实运动测试都必须在 EP Core 上进行；本包不会在当前沙箱里连接或驱动机器人。

## 包含内容

- `acceptance-checklist.md`：验收阈值、视频双路径记录、浏览器连通性和 30 次故障注入记录方法。
- `field-test-guide.md`：从教室摆场、只读烟测到延迟与安全故障测量的详细现场流程，以及本包当前不能测的边界。
- `python-38-setup.md`：在课堂 Windows 主机上安装隔离 Python 3.8 环境的步骤。
- `probe.py`：基于 DJI 官方 RoboMaster Python SDK 的连接、视频解码、底盘状态订阅、单次低速命令超时试验和 JSONL/CSV 日志探针。
- `requirements.txt`：固定官方 SDK 版本。

## 重要范围说明

DJI SDK 的公开 EP 摄像机 API 会把 H.264 解码成图像帧；SDK 的公开 Python API 没有把原始 H.264 帧直接交给浏览器的接口。因此 `probe.py` 可检查 SDK 解码路径和底盘控制/租约行为，但**不能单独完成原始 H.264 直通与浏览器转码两条 WebRTC 路径的对比**。原始流位于 DJI 文档列出的 TCP 视频端口，需要单独的浏览器视频 relay；清单中把两组测量分开记录，不能把 SDK 帧率当成端到端视频延迟。

SDK 和明文协议接口均来自 DJI 官方公开资料；本包不使用 APK 逆向代码或逆向协议发现。视频端口/明文命令的使用须按官方文档执行。

## 现场运行顺序

1. 按 `python-38-setup.md` 建立独立 venv。
2. 先读 `field-test-guide.md` 的安全门和阶段说明，再按 `acceptance-checklist.md` 记录结果。
3. 单台机器人先用 `probe.py --observe-seconds 30` 自动发现并验证 EP Core、摄像头和底盘遥测；同网多台时加 `--sn <机器人序列号>` 指定目标。
4. 在有人值守、机器人周围清空并装有记录载荷时，再执行单次低速命令超时试验；每种故障场景应由观察员逐次注入、逐次记录。
5. 用清单分别记录 H.264 直通和转码的浏览器实测；不要把脚本的 SDK 解码帧到达时间当成浏览器 glass-to-glass 延迟。

## 安全边界

运动测试需由一名操作员和一名观察员进行。脚本默认只观察；运动必须显式传入 `--arm-motion` 并在终端二次确认。速度上限为 0.15 m/s，且只发一条带 SDK timeout 的速度命令。此 timeout 依赖 Python 进程仍在运行，不覆盖 bridge 崩溃、电脑睡眠或 Wi-Fi 断连；不能据此宣称这些故障已具备安全保护。物理停稳时间和距离须用外部录像测量。任何一次未触发停控或超过验收线，立即停止后续试验。
